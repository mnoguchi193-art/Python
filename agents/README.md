# Agent Orchestration (エージェント・オーケストレーション)

複数のエージェント (ワーカー) に仕事を振り分け、結果をまとめる **オーケストレーション
の基本パターン** を、標準ライブラリだけで実装した学習用デモ群です。Claude Code の
**サブエージェント** (`Task`/`Agent` ツールで起動し、独立したコンテキストで作業して
レポートだけを親に返す仕組み) の考え方を、Python のコードとして体験できます。

> ⚠ **教育目的のおもちゃモデルです。** ここでの「エージェント」は単なる関数やスレッド
> であり、LLM やネットワーク呼び出しは行いません。Claude Code の実機能の再現ではなく、
> その背後にある *設計パターン* を示すものです。

## 構成 / Modules

| File | パターン | 内容 |
|---|---|---|
| `delegation.py` | 委譲 (typed subagents) | オーケストレーターがタスクの種類ごとに専門サブエージェントを選んで渡し、レポートだけを集約 |
| `parallel_fanout.py` | 並列ファンアウト | 独立した待ち時間律速のタスクを `ThreadPoolExecutor` で同時実行し、逐次実行と速度比較 |
| `map_reduce.py` | マップ・リデュース | コーパスを分割して各ワーカーが独立に集計 (map)、部分結果を統合 (reduce) |
| `pipeline.py` | パイプライン | 単一責務のエージェントを直列に連結 (proposer → critic → reviser) |

## 実行 / Run

```bash
python3 agents/delegation.py
python3 agents/parallel_fanout.py
python3 agents/map_reduce.py
python3 agents/pipeline.py
```

外部ライブラリ不要 (標準ライブラリのみ)。各ファイルは独立しており、相互 import は
ありません。

## Claude Code のサブエージェントとの対応 / Mapping to Claude Code subagents

Claude Code のサブエージェントは、親エージェントが `Task` (`Agent`) ツールで起動する
補助エージェントです。各デモはその特徴の一面に対応します。

1. **型による委譲 (`delegation.py`)** — `subagent_type` で種類を選び、自己完結した
   タスクを渡す。サブエージェントは自分のタスクだけを見て (独立コンテキスト)、
   結果レポートを返す。親はレポートだけを受け取り、途中経過は見ない。
2. **並列実行 (`parallel_fanout.py`)** — 独立したサブエージェントは同時に起動できる。
   サブエージェントは待ち時間律速なので、並列化で「待ちの合計」が「最長の待ち」に縮む。
3. **広い探索と統合 (`map_reduce.py`)** — 大量のファイル探索などを分担させ (fan-out)、
   各自が自分の範囲だけを読み、親は統合した結論だけを保持する。
4. **直列の連携 (`pipeline.py`)** — 常に並列とは限らない。生成→批評→修正のように、
   単一責務のエージェントを鎖状につなぐ使い方もある。

共通する設計思想は **「コンテキストの分離」と「レポートだけの受け渡し」** です。各
サブエージェントに専用の作業領域を与え、親の文脈を散らかさずに、必要な結論だけを
戻す —— これが、大きなタスクを小さく分けて速く正確に片付けるための核心です。
